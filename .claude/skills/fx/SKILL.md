# fx

The tool of the Fuxion workspace: it generates what the repositories share from `_fx/` (`fx sync`), checks it (`fx doctor`), mounts and parks repositories, makes worktrees and versions from git. This skill is generated from `fx describe`: `fx describe --output json` has the same, as data.

## How an agent runs fx

- **Ask for JSON**: `--output json` writes one document on stdout (`schema`, `ok`, the data of the command and `diagnostics`, each with `code`, `severity`, `message`, `file`, `line` and `fix`). `fx schema <id>` gives the JSON Schema of each `fx-*/1`. `--output ndjson` writes events as the work goes on; the last line is the document.
- **Nothing is asked without a person**: pass every value. A missing one ends with exit code 2 and says what is missing.
- **Never `fx ui`**: it needs a person at a terminal (exit code 2 without one).
- **Before changing, `--dry-run`** where a command takes it: it says what would change. The commands that edit the configuration also say what `fx sync` would do with the change.
- **Never edit what fx generates** (files with the header `GENERATED by Fuxion.Tool (fx)`) nor `_fx/.inherited/`: change the yaml of the module in `_fx/` (or use the commands that edit it) and run `fx sync`. `fx doctor` checks without changing anything.
- **To work on a branch apart, `fx worktree add <branch>`**, never `git worktree add`: fx puts it in its place, with the repositories it needs, and the build sees it as a closed tree. `fx worktree remove <branch>` when done.

## The files of the coding agents (the harness)

`AGENTS.md`, `CLAUDE.md`, `.claude/rules/`, `.claude/skills/` and `.agents/skills/` are generated by fx in every root of fx: never edit them, `fx sync` writes them again. Their source is `_fx/harness/`, and what the workspace gives in `_fx/.inherited/harness/`:

- `_fx/harness/harness.yaml` lists the rules and the skills, each with its `applies-to` (tags or repositories; it decides for the root itself too; without it, for everyone) and, for a rule, its `paths`.
- A rule is `_fx/harness/rules/<name>.md`, Markdown that starts with its `##` title. Without `paths` it goes into `AGENTS.md`; with them, into `.claude/rules/<name>.md`, and `AGENTS.md` says when to read it.
- A skill is the folder `_fx/harness/skills/<name>/`: its `SKILL.md` (a front matter with `name: <name>` and a `description`) and whatever it needs, copied to `.claude/skills/` and `.agents/skills/`.
- To change what the agents are told: write the rule or the skill there (in the workspace, for what is inherited), declare it in `harness.yaml` and run `fx sync`. `fx sync --adopt` moves into `_fx/harness/` what was written by hand in those files.
- The rule and the skill named `fx` are fx's own: every root of fx gets them.

### `fx sync [<module>]`

Generate and update what fx owns here and in everything mounted below, from the _fx configuration.

- `<module>` (optional): Only this module: workspace, dotnet or harness.
- `--dry-run`: Show what would change, without writing.
- `--offline`: No network: do not fetch the repositories.
- `--adopt`: Take over files written by hand (without the GENERATED header).
- `--only`: Only this root, not what is mounted below it (nor the map of FxReference).
- `--parent-ref` <string>: Read the parent from its remote, on this branch (to try what it gives, without versioning the choice).

### `fx doctor [<module>]`

Check, without changing anything, that what fx owns here and below is right.

- `<module>` (optional): Only this module: workspace, dotnet or harness.
- `--offline`: No network: do not ask the remotes.
- `--only`: Only this root, not what is mounted below it (nor the map of FxReference).
- `--parent-ref` <string>: Read the parent from its remote, on this branch (to try what it gives, without versioning the choice).

## Global options

- `--root` <string>: Folder to act on (the current one by default).
- `-w`, `--workspace`: Act on the whole workspace, from anywhere inside it.
- `--output` <string> (`human`, `json`, `ndjson`): human (by default); json, a document; ndjson, events and then the document. Stable, always in English.
- `-v`, `--verbose`: More detail, on stderr.
- `--plain`: No colors or borders.
- `--non-interactive`: No questions and no live progress, whatever the terminal (for scripts and CI).
- `--lang` <string> (`en`, `es`): Language of the messages: en or es (by default, FX_LANG or the system's).

## Exit codes

- `0`: Done, without errors (there may be warnings).
- `1`: Done, with errors: the diagnostics say which and how to fix them.
- `2`: Wrong usage: an unknown command or option, a missing value, or something fx would ask with no one to ask.
- `130`: Cancelled (Ctrl+C).
