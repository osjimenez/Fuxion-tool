# fx

The tool of Fuxion's spaces: it generates what the repositories share from `_fx/` (`fx sync`), checks it (`fx doctor`), mounts and parks repositories, makes worktrees and versions from git. This skill is generated from `fx describe`: `fx describe --output json` has the same, as data.

## How an agent runs fx

- **Ask for JSON**: `--output json` writes one document on stdout (`schema`, `ok`, the data of the command and `diagnostics`, each with `code`, `severity`, `message`, `file`, `line` and `fix`). `fx schema <id>` gives the JSON Schema of each `fx-*/1`. `--output ndjson` writes events as the work goes on; the last line is the document.
- **Nothing is asked without a person**: pass every value. A missing one ends with exit code 2 and says what is missing.
- **Never `fx ui`**: it needs a person at a terminal (exit code 2 without one).
- **Before changing, `--dry-run`** where a command takes it: it says what would change. The commands that edit the configuration also say what `fx sync` would do with the change.
- **Never edit what fx generates** (files with the header `GENERATED by Fuxion.Tool (fx)`) nor `_fx/.inherited/`: change the yaml of the module in `_fx/` (or use the commands that edit it) and run `fx sync`. `fx doctor` checks without changing anything.
- **To work on a branch apart, `fx worktree add <branch>`**, never `git worktree add`: fx puts it in its place, with the repositories it needs, and the build sees it as a closed tree. `fx worktree remove <branch>` when done.

## The files of the coding agents (the harness)

`AGENTS.md`, `CLAUDE.md`, `.claude/rules/`, `.claude/skills/` and `.agents/skills/` are generated by fx in every root of fx: never edit them, `fx sync` writes them again. Their source is `_fx/harness/`, and what the parent gives in `_fx/.inherited/harness/`:

- `_fx/harness/harness.yaml` lists the rules and the skills, each with its `applies-to` (tags or repositories; it decides for the root itself too; without it, for everyone) and, for a rule, its `paths`.
- A rule is `_fx/harness/rules/<name>.md`, Markdown that starts with its `##` title. Without `paths` it goes into `AGENTS.md`; with them, into `.claude/rules/<name>.md`, and `AGENTS.md` says when to read it.
- A skill is the folder `_fx/harness/skills/<name>/`: its `SKILL.md` (a front matter with `name: <name>` and a `description`) and whatever it needs, copied to `.claude/skills/` and `.agents/skills/`.
- To change what the agents are told: write the rule or the skill there (in the parent, for what is inherited), declare it in `harness.yaml` and run `fx sync`. `fx sync --adopt` moves into `_fx/harness/` what was written by hand in those files.
- The rule and the skill named `fx` are fx's own: every root of fx gets them.

## The catalog of documents (`fx doc`)

In a space with `_fx/docs/`, its catalog (`_docs` by default) follows a documentation standard: every document is a pair, its Markdown and its sidecar `TYPE-slug.meta.json` (identity, type, status, relations, integrity), which only fx writes.

- **Create with `fx doc new <type> <title>`**, never by hand: it names the pair, puts it in its place (`_records/YYYY/MM/` for a historical type) and seals its sidecar. `fx doc schema` gives the types, their statuses and profiles.
- **Edit the Markdown, then `fx doc finalize <document>`**. Never edit a sidecar by hand: its hash says so. A frozen document (historical, no longer open, once that state is committed) only takes a correction: `fx doc finalize <document> --correction <note>`; until then, it is finalized like an open one. Any other document but a view may record a correction too.
- **Statuses and relations with `fx doc status` and `fx doc relate`**; the entries of a register with `fx doc entry add|set|close`; a short key with `fx doc key`; a stable document moves with `fx doc move`. As the target of a relation, an entry is named by its key, its identity, `<register>#<name>`, or its name if no other entry has it.
- **A document created since the last commit is removed with `fx doc discard <document>`**, never by hand: it also undoes what its `supersedes` did.
- **Check with `fx doc check [<documents>]`** after a change (`--branches`, also against the remote branches); `fx doctor` checks the whole catalog.
- **The actor of a change**: `fx doc --actor`, or `FX_DOCS_ACTOR`, one of the `actors` of `_fx/docs/docs.yaml`; `new`, `adopt` and `key` need it, and `entry add` when it reserves a key.
- The views (documents `view`) are generated by `fx sync`: never edit them.

- `--actor` <string>: Who makes the change, one of the actors of docs.yaml; by default, the variable FX_DOCS_ACTOR. new, adopt and key need it, and entry add when it reserves a key.

### `fx doc entry list <register>`

Lists the entries of a register.

- `<register>` (required): The register: its path or its identity.
- `--open`: Only the open ones.
- `--closed`: Only the closed ones.
- `--actor` <string>: Who makes the change, one of the actors of docs.yaml; by default, the variable FX_DOCS_ACTOR. new, adopt and key need it, and entry add when it reserves a key.

### `fx doc key <register> [<title>]`

The next key of a register that uses them, reserved by its provider (repo: the next of the register, in every branch; git: an atomic reservation on the remote); with --confirm, its provisional keys reserved now.

- `<register>` (required): The register: its path or its identity.
- `<title>` (optional): What the key is for (it goes in the reservation).
- `--confirm`: Reserves now the provisional keys of the register.
- `--dry-run`: Says the key it would give, reserving nothing.
- `--actor` <string>: Who makes the change, one of the actors of docs.yaml; by default, the variable FX_DOCS_ACTOR. new, adopt and key need it, and entry add when it reserves a key.

### `fx worktree add <branch>`

Create a worktree of a branch in the nearest space (or --in), with where you are mounted in it.

- `<branch>` (required): The branch.
- `--in` <string>: The space where it goes: one of those above, by name, full name or path.
- `--required`: Also the required mounts of what is mounted, down.

### `fx worktree mount <branch> [<targets>]`

Mount more of the tree in a worktree: repositories (with the spaces on the way) or paths left out.

- `<branch>` (required): The branch.
- `<targets>` (one or more): Repositories (name, path or full name) or paths left out.
- `--required`: Also the required mounts of what is mounted, down.

### `fx worktree unmount <branch> [<repositories>]`

Take repositories out of a worktree (not with uncommitted changes).

- `<branch>` (required): The branch.
- `<repositories>` (one or more): Repositories (name or path).

### `fx worktree list`

The worktrees of the spaces around here.

### `fx worktree remove <branch>`

Remove a worktree (not with uncommitted changes); the branches fx created go if git deletes them safely.

- `<branch>` (required): The branch.

### `fx version`

The version this repository would build now, from its git history.

- `--explain`: Show how the version was calculated.

### `fx version tag [<X.Y>]`

Create the tag version/X.Y.0 on HEAD to start a new minor or major (local; push it yourself).

- `<X.Y>` (optional): The new major and minor, like 11.3.

### `fx self update`

Update fx to its latest release (or the one of --version), as it was installed.

- `--version` <string>: The version to install (also an older one); the latest release, without it.
- `--check`: Only say whether there is another release; change nothing.

### `fx describe`

fx described by itself: every command, what it outputs and what it does (with --output json, for agents).

- `--skill`: The skill of fx for coding agents (its SKILL.md), made from these same descriptions

### `fx schema [<id>]`

The JSON Schema of an output of fx; without an id, the list of them.

- `<id>` (optional): The id of the schema (fx-sync/1…).

## Global options

- `--root` <string>: Folder to act on (the current one by default).
- `-s`, `--space`: Act on the nearest space that mounts others, itself included, from anywhere inside it.
- `--output` <string> (`human`, `json`, `ndjson`): human (by default); json, a document; ndjson, events and then the document. Stable, always in English.
- `-v`, `--verbose`: More detail, on stderr.
- `--plain`: No colors or borders.
- `--non-interactive`: No questions and no live progress, whatever the terminal (for scripts and CI).
- `--lang` <string> (`en`, `es`): Language of the messages: en or es (by default, FX_LANG or the system's).

## Exit codes

- `0`: Done, without errors (there may be warnings).
- `1`: Done, with errors: the diagnostics say which and how to fix them.
- `2`: Wrong usage: an unknown command or option, a missing value, or something fx would ask with no one to ask.
- `130`: Cancelled (Ctrl+C).
